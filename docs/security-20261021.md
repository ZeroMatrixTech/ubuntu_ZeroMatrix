# CA security baseline — 2026-10-21

USN-8944-1 removes trust in the compromised emSign ECC Root CA - G3.
The reviewed Ubuntu 26.04 package is pinned by version, bytes and SHA-256 in
`config/security-baseline.json` and the acquisition lock. `make security-inputs`
fetches that exact package without installing anything on the host.

A fresh `make rootfs` installs it inside the private build namespace, regenerates
the CA bundle, and synchronizes both trust material and package metadata to the
Live overlay. Target and Live must pass package-version and DER fingerprint
checks before packing. `build-online.py` repeats those checks before ISO assembly,
including for caller-selected ROOTFS_BUILD caches. The security policy and verifier
participate in the cache fingerprint. Historical base Ubuntu input files and old
release ISOs remain unchanged as provenance, not approved new security releases.

Use a fresh rootfs directory and version (default 0.2.0-rc4), then build both profiles:

```
make isos
make verify-iso
```

`build/rootfs-0.2.0-rc4/security-verification.json` records package and effective
bundle evidence. Installation/boot acceptance is separate from packing and hashing;
do not infer successful VM/physical installation from a completed ISO build.
Do not redistribute rc1–rc3 as security-current images. Existing installations,
snaps, browsers and private Java/Electron runtimes require their own update checks.

Reference: https://ubuntu.com/security/notices/USN-8944-1

Legacy ISO generation is disabled in both entry points because it retains the
unpatched upstream Live image. Archived offline inputs remain preserved and
are not a supported way to publish a new security-current ISO.
