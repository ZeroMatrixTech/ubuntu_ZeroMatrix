# Trust-store security baseline — 2026-10-21 (revised 2026-10-22)

Eight eMudhra intermediate CAs (16 certificates including Sectigo cross-signs) have
recoverable private keys (CVE-2026-91403). They validate through four roots:
AAA Certificate Services (Sectigo), emSign ECC Root CA - G3, emSign Root TLS CA - G3
and emSign Root CS CA - G3. Their PEMs are in `config/security-denied-roots.pem`;
the reviewed SHA-256 list in `config/security-baseline.json` must match that file
or verification fails.

Two Ubuntu 26.04 packages are pinned by version, bytes and SHA-256 in
`config/security-baseline.json` and the acquisition lock:

- `ca-certificates 20260816ubuntu0.26.04.1` (USN-8944-1) removes emSign ECC Root CA - G3
  from the PEM bundle used by OpenSSL, GnuTLS and most runtimes;
- `libnss3 2:3.120-1ubuntu2.2` (resolute-security, 2026-10-20) removes emSign ECC Root CA - G3
  and AAA Certificate Services from the NSS builtins (`libnssckbi.so`) used by Evolution/Camel,
  Poppler signatures, xmlsec1-nss and volume_key. The rc4 rootfs still carried 2.1 with both roots.

`make security-inputs` fetches the exact packages without installing anything on the host.
A fresh `make rootfs` installs them inside the private build namespace, regenerates the CA
bundle, and synchronizes package records, metadata and any shadowed package files plus
trust material to the Live overlay. Target and Live must pass package-version checks, a
DER fingerprint check of the CA bundle and a scan of the NSS builtins for the DER of all
four roots before packing. Live files that the overlay does not carry are checked in the
target layer they show through from. `build-online.py` repeats those checks before ISO
assembly, including for caller-selected ROOTFS_BUILD caches. The security policy, denied
roots and verifier participate in the cache fingerprint, so rc4 caches are rejected.
Historical base Ubuntu input files and old release ISOs remain unchanged as provenance,
not approved new security releases.

Use a fresh rootfs directory and version (default 0.2.0-rc5), then build both profiles:

```
make isos
make verify-iso
```

`build/rootfs-0.2.0-rc5/security-verification.json` records package, CA bundle and NSS
builtins evidence. Installation/boot acceptance is separate from packing and hashing;
do not infer successful VM/physical installation from a completed ISO build.
Do not redistribute rc1–rc4 as security-current images. Existing installations,
snaps, browsers and private Java/Electron runtimes require their own update checks.
In particular the seeded `core24_1643` snap still trusts AAA Certificate Services and
emSign ECC Root CA - G3, and no core24 channel carried a fix on 2026-10-22. This baseline
covers the trust-store packages only; other pending resolute-security updates are not
applied by it.

References:
- https://ubuntu.com/security/notices/USN-8944-1
- https://openjdk.org/groups/vulnerability/advisories/2026-10-21
- https://emudhra.we-have-a-problem.com/

Legacy ISO generation is disabled in both entry points because it retains the
unpatched upstream Live image. Archived offline inputs remain preserved and
are not a supported way to publish a new security-current ISO.
